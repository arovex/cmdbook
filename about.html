About CmdBook

A command reference that explains the parts people usually have to look up twice.

What this is

CmdBook is a static reference for commands used in day-to-day development and security work. Each entry has four parts: the command, a plain-English description, a note on when to use it, and a breakdown of its flags. Entries are grouped by topic and can be searched from any page.

The explainer on the Explain page uses the same data. It splits a command into tokens, identifies the program, and resolves flags from the dictionary in data/commands.json. Unknown programs and flags are labelled as unknown instead of being guessed.

Entry format

Entries live in data/<topic>.json as arrays. A minimal entry looks like this:

{
  "id": "tar-extract",
  "command": "tar -xzvf backup.tar.gz",
  "plain": "Extract a .tar.gz archive into the current folder.",
  "when": "You downloaded a .tar.gz and need the files inside.",
  "safety": "safe",
  "tags": ["files", "archives"],
  "flags": [
    { "flag": "-x", "meaning": "extract" },
    { "flag": "-z", "meaning": "decompress gzip" }
  ],
  "related": ["find-name"]
}

Required fields are id, command, plain, when, safety, and tags. safety is one of safe, caution, or danger. related must reference IDs that exist.

Contributing

To add a command:

  • Add the entry to the matching topic file in data/.
  • If the explainer should understand the program, add it to data/commands.json.
  • Run python scripts/build_bundle.py to validate the data and regenerate data/bundle.js.
  • Run python scripts/build_bundle.py --check before committing. CI runs the same check.

Keep plain focused on what the command does, and use when for the situation that makes you reach for it. Mark destructive commands as danger.
